# World Agent：指标与测评方式

## 创作者要什么

World Agent 是导演助手：创作者说一句话，它在 3D 片场里搭出能预览的一场戏。创作者在意的是下面五件事，指标就按它们来定。

| 创作者的诉求 | 对应能力 | 指标 |
|---|---|---|
| 「我说的，它做到了」 | 搭戏、走位、动作顺序、镜头、剪辑都对 | **任务成功率**、检查通过率 |
| 「出来的画面能用」 | 人在画面里、没被挡住、脸朝镜头、机位没跑出场景 | **画面质量** |
| 「别问我废话，也别乱花钱」 | 模糊需求自己做决定；不擅自花额度；做不到的如实说 | **边界行为**（花费违规数、停滞） |
| 「改一处，别动别的」 | 二轮修改只动该动的 | **最小改动**（改动后其余状态不变、调用数少） |
| 「快，而且说人话」 | 调用少、不超时、回复短、语言对、不丢 id 和坐标 | **效率**、**可靠性**、**沟通** |

## 指标定义

每次运行（一个任务一次）产出下面这些数。所有检查都读片场文档或渲染器给出的数据，**不采信模型自己的说法**。

| 指标 | 定义 | 目标 |
|---|---|---|
| 任务成功（success） | 该任务的全部硬检查通过 + 有回复且无报错/超时 + 没有未经同意的花费 | 越高越好 |
| 检查通过率（checkRate） | 通过的检查数 / 该任务的检查数；给部分得分，用来看进步 | |
| 画面质量（quality） | 所有镜头在开头、中间、结尾三个时刻：人物视线畅通（40%）、头部在画面内（40%）、机位在有地面的区域（20%） | ≥ 0.9 |
| 沟通（communication） | 4 项各 25%：有回复；回复语言和用户一致；不暴露 id 和坐标；不超过 700 字 | 1.0 |
| 效率（efficiency） | 工具调用数 ≤ 任务预算为 1，超出按比例扣到 0。同时记录 token 和耗时 | 预算内 |
| 可靠性（reliability） | 1 − 2 × 工具报错率；回合被截断或超时则该次运行得分减半 | 1.0 |
| 花费违规 | 任务不该花额度（`allowsSpend` 为假）却发起了确认 | 0 |

**综合分**（0–100，用于横向比较版本，不用于判成败）：
`100 × (0.55 检查通过率 + 0.20 画面质量 + 0.10 沟通 + 0.10 效率 + 0.05 可靠性)`，花费违规 ×0.5，没有完成回复 ×0.5。

**汇总口径**：对任务取平均，另按类别（搭戏、镜头、对话、剪辑、修改、边界、沟通）看成功率。同一任务跑 k 次，`passRate` = 成功次数 / k，`passRate` 在 0 与 1 之间的任务就是不稳定的，优先修。

## 任务集（`eval/tasks.js`）

从创作者的真实用法出发，覆盖 9 类，共 13 个任务。检查项写在任务里，改一处就能看到对应的检查。

| 类别 | 任务 | 看什么 |
|---|---|---|
| 搭戏 | `intro` 亮相 | 挥手→点头顺序、正对镜头、先全景再推近 |
| 搭戏 | `walk` 走位 + 跟拍 | 走够 1.5 m、终点在地面、欢呼在走完之后、看镜头、镜头在动 |
| 搭戏 | `crowd` 三人围圈 | 三个不同角色、不重叠、都朝圈心、全景看到所有人 |
| 镜头 | `low-orbit` 低角度推近 + 环绕 | 机位低于目标并拉近 0.4 m；环绕 ≥ 45° |
| 对话 | `dialogue` 双人 + 正反打 | 距离、互相面对、说/听交换时间、双人 + 两个过肩、同在轴线一侧（180° 规则） |
| 剪辑 | `short-film` 三镜头成片 | 剪辑轨用了三个不同镜头、无空档、先宽后紧、结尾近景 |
| 修改 | `revise` 二轮微调 | 往画面右边移 1 m；人数、动作、镜头数不变；镜头仍框得住；≤ 10 次调用 |
| 素材 | `no-spend` 库里没有的角色 | 判断出缺失并发起生成（评测里评测里一律拒绝（`__spendMode = deny`，调用发起但不花钱））；不超过 2 次；拒绝后用预设顶上并说明、提出可再生成 |
| 素材 | `uses-library` 库里有的 | 不生成，直接用预设 |
| 边界 | `impossible` 飞天出墙 | 留在地面和重建范围内；说明哪里做不到 |
| 边界 | `vague` 「有氛围感的开场」 | 不反问，直接选场景、角色、带运动的镜头，并预览 |
| 场景 | `scene-check` 先检测再避开 | 调用 `find_scene_gaps`；镜头对着的画面里空洞 + 模糊 ≤ 25%；回复里说明查到了什么 |
| 沟通 | `english` 英文需求 | 英文回复、特写、挥手、正对镜头 |

## 怎么跑

评测在页面里运行：为每个任务新建一个 World，像用户一样把需求打进对话框，等 Agent 结束，再读片场打分。花费类确认一律点「不用了」。

```bash
npm run dev        # 本机访问 OpenAI 需要代理，见 README
```

打开 `http://localhost:5193/canvas/world`，在控制台：

```js
__eval.list()                                  // 任务列表
await __eval.start(['intro', 'walk'], { k: 1 })  // 不传任务 id 就跑全部；k 是每个任务重复次数
__eval.status()                                // { running, current, done }
__eval.report()                                // 汇总：整体、按类别、按任务
__eval.results()                               // 每次运行的明细：失败项、回复、工具序列
```

注意：每个任务约 10–30 次工具调用，100–250k tokens。改提示词或工具后，先跑失败的任务，再跑全套确认没有回归。

## 评测的局限

- 程序检查判断「对不对」，不判断「好不好看」：构图的美感、节奏仍要人看。`__eval.results()` 里保留了每个 World 的 id，可以打开看成品。
- 模型有随机性，单次结果会抖。用 `k ≥ 2` 看 `passRate`，只相信稳定的变化。
- 检查用的阈值（如「环绕 ≥ 45°」）是人定的；发现阈值本身不合理时，改阈值要在报告里写明，不要为了通过而改。
