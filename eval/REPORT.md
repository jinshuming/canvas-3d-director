# World Agent 评测报告

- **日期**：2026-10-30
- **模型**：`gpt-6-luna`（OpenAI Responses API）
- **场景**：现代客厅（Viggle 生成的 splat）
- **方法**：每轮新建一个片场，像真实用户一样在对话框里打字发送。Agent 回合结束后，用程序读取片场文档和渲染器给出的数据，逐项检查结果（`eval/harness.js`、`eval/grade.js`、`eval/tasks.js`）。

## 评测中发现并已修复的问题

1. **过度打磨、没有收尾**（第 2 轮）：
   - **现象**：联系表做了 8 次，运镜调了 11 次，用完 40 轮模型调用后没有给出回复。
   - **修复**：
     - 系统提示里写明预算（简单需求约 15 次调用，图片类工具有上限，最多修两轮）。
     - 只剩 5 轮时提醒 Agent 收尾。
     - 最后一轮用 `tool_choice: none` 强制给出文字回复。
     - 降低 `look` 和联系表的图片分辨率。
   - **效果**：同一个需求的 token 从 675k 降到 245k，耗时从 411 s 降到 129 s。
2. **中文动作名对不上**（第 2 轮）："欢呼"在英文命名的预设里搜不到，最后用了 Jump。修复：给预设动作和角色加中文别名；`list_assets` 一次返回全部，并提示不要逐词搜索。
3. **"转身看镜头"转错方向**（第 2 轮）：`face: "camera"` 指的是编辑器的视角，不是镜头的相机。修复：`face` / `end_face` 可以传镜头 id，提示词里也说明了"看镜头"就是看那个镜头的相机。
4. **截图卡死**（第 3 轮）：浏览器面板在后台时，浏览器会暂停 `requestAnimationFrame`，截图和导出会一直等下去。修复：`StageRenderer.frames()` 每帧最多等 120 ms，等不到就手动绘制。

## 还没解决的问题

- **过肩镜头质量一般**（第 3 轮）：程序检查通过，但画面里前景人物占得太多，说话的人是侧脸。原因是缺少专门的"过肩"构图预设，Agent 只能用普通构图拼出来。建议给 `camera_move` / `frame_shot` 加 `over_shoulder` 和 `two_shot` 双人构图。
- **用重复的角色凑数**（第 5 轮）：没有武士，就又用了一个维京预设。可以接受，但最好在回复里更明确地说"这是同一个模型"。
- **成本**：复杂需求每次仍然要 20–30 万 token，主要花在截图和联系表上。可以考虑在只需粗看时用 `detail: "low"` 的图片输入，或者先用缩略图判断，必要时再看大图。
- **网络**：本机访问 OpenAI 需要走代理，已经配置在 dev server 的启动参数里（`NODE_USE_ENV_PROXY=1` + `HTTPS_PROXY`）。换一台机器运行时需要相应调整。

## 第二轮：双人构图预设

### 改了什么

- **新的构图方式**：`frame_shot` / `camera_move` 加了 `framing`，取值 `over_shoulder`（过肩）或 `two_shot`（双人），配合 `with` 指定第二个人。实现在 `framePair`（`src/stage/framing.ts`）。
  - **过肩**：机位在前景人物身后 0.8 m、侧出 0.32 m、眼睛高度；镜头焦距按景别自动算（约 19–21°，接近长焦）；主体放在远离肩膀那一侧的三分线上。
  - **双人**：机位垂直于两人连线；距离超过 2.2 m 时自动换成广角，不会退到房间外面。
- **180° 规则**：同一对人的所有镜头自动站在轴线同一侧，`line_side` 用来选边：
  - `auto`（默认）：用渲染器判断哪一侧机位下面有地面、视线更清楚。
  - `other_side`：整体换到另一侧。
- **双人构图自己选镜头**：模型会把所有可选参数都填上（比如 `fov: 40`、`flip: false`），这会关掉自动选镜头和自动选边，所以双人构图现在忽略 `fov`。选边参数的取值也改成了模型照着填不会出问题的 `auto | other_side`。
- **工具结果里加说明**：告诉模型过肩镜头里前景人物被画框切掉是正常的，避免它反复"修"一个本来没问题的镜头。

### 顺带发现并修复的两个 bug

1. **对话动作让角色转身 90°**：这是第一轮"说话的人是侧脸"的真正原因。
   - **原因**：Talk / Listen / Nod 这几个预设动作在录制时演员是侧着站的。用肩线测量第 0 帧的朝向，Talk 是 +87°，Listen 是 +78°，Nod 是 +119°；Idle、Walk、Wave、Cheer 都在 ±11° 以内。
   - **修复**：
     - 引擎新增 `Armature.probeFacing`，用两侧锁骨连线算身体朝向，不依赖骨骼的轴向约定。
     - `StageRenderer` 在第一次用某个片段时测一次朝向；超过 30° 就把身体转回来，根运动的位移也跟着一起转。
     - 效果：角色在任何动作开始时，都朝向文档里设定的方向。
2. **`look` 偶尔拍到错误的镜头**：
   - **原因**：`frame_shot` 会让编辑器预览这个镜头，而 React 要晚一帧才把视角推给渲染器。如果紧接着调用 `look`，这一帧正好落在截图期间，拍到的是上一个预览的视角。
   - **修复**：`renderStill` 先等编辑器的更新落地，再接管视角。

- 至少有三个镜头；
- 其中有一个双人镜头；
- 两个人各有一个能看到正脸的过肩镜头；
- 所有镜头的机位都在两人连线的同一侧。

### 还没解决的问题

- **前景人物太宽**：维京女战士带兜帽，比较宽，反打镜头里她占了画面将近一半。过肩机位的侧向偏移目前是固定值，可以改成按前景人物的实际包围盒来算。
- **建立镜头还是费调用**：两人站的位置正好在沙发前面，双人机位容易被家具挡住，Agent 会花一两轮去调。`auto` 选边已经先做了一次判断，下一步可以在同一侧多试几个 `side` 角度，自动选最清楚的一个。

## 下一步建议

1. 把这 5 个任务和检查器整理成固定的回归集，每次修改提示词或工具描述后重跑。
2. 补上过肩镜头和双人镜头的构图预设，增加镜头语言类任务（正反打、建立镜头加切近）。
3. 加入视觉模型评审，用来给"好不好看"打分，弥补程序检查只能判断"对不对"的不足。
